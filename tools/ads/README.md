# Town ad groups

Generated by `tools/build-town-ads.py`. Three files, all Google Ads Editor
paste format.

The problem these fix: every ad in the account pointed at `/estimate/`, so a
search for "masonry weston ma" landed on a generic form. The 13 town pages
already carry five CTAs each into the same estimate flow, so pointing the ads
at them costs nothing in conversion and buys back landing-page relevance —
which is a third of Quality Score, and Quality Score is what sets the price
per click.

| File | What it loads |
|---|---|
| `town-ads.csv` | 13 responsive search ads, one per town, each with that town's final URL |
| `town-keywords.csv` | 338 keywords, 26 per town |
| `negatives.csv` | 44 campaign-level negatives |

## Loading them

Google Ads Editor → Account → Import → Paste text. One file at a time.
Keywords and ads can go in any order; do negatives first if you want the
list live before anything can spend.

`Campaign` in all three files is `Search-1`. If the live
campaign is named something else, find-and-replace that column before
pasting or Editor will offer to create a second campaign.

## What is in the ad copy

Every claim is one the site already makes and can keep:

- the one-year workmanship warranty, as written in `tools/offers.json`
- free on-site estimates
- insured, own crew
- built to the town's frost depth

No years in business, no job counts, no ratings, no "licensed" — the HIC
registration is not in hand and it does not go in an ad until it is.

## Regenerating

    python3 tools/build-town-ads.py

Reads `tools/towns.json`, so a new town added there gets an ad group, a set
of keywords and a landing URL without touching this directory. Headline and
description length limits are enforced at build time — anything over 30 or
90 characters is dropped, and the build reports it rather than shipping a
disapproved ad.
